What it does

Luddite Scout reads a public GitHub repository and reports what a careful person would want to know before pointing a coding agent at it, or building it:

  • S1 Repository setup. Security policy, private vulnerability reporting, licence, archive and fork status, open pull requests.
  • S2 Agent instruction files. Files such as CLAUDE.md, AGENTS.md, .claude/, .mcp.json, editor tasks and dev container config that an agent or editor may read or execute.
  • S3 Hidden Unicode. Bidirectional controls, tag characters and zero-width characters that hide text from a human reviewer.
  • S4 GitHub Actions. Risky trigger and checkout combinations, untrusted input inside shell steps, unpinned actions, broad permissions.
  • S5 Dependencies. Lockfiles checked against the OSV advisory database, plus the OpenSSF Scorecard result where one exists.
  • S6 Build-time code. Scripts that run when the project is installed, built, or opened, such as build.rs, install scripts and .envrc.

Every check reports whether it ran in full, ran partially, or was skipped, and why. A skipped check is never shown as a pass.

What it does not do

  • It does not run any code from the repository, and it does not use an AI model.
  • It does not review code for vulnerabilities. Its findings are pattern matches and need a human to judge them.
  • It only reads public repositories, and only the default branch.

Data handling

The site is static. There is no server of ours involved, and nothing is stored, logged or shared by this site. Your browser talks directly to these services:

  • api.github.com: repository details, file list, pull requests, vulnerability reporting status.
  • raw.githubusercontent.com: file contents, pinned to the commit being reviewed.
  • api.osv.dev: package names and versions from the repository's lockfiles, to look up advisories.
  • api.securityscorecards.dev: the repository name, to look up its Scorecard result.

Those services see your IP address and what you looked up, under their own privacy policies. The Content Security Policy on the scanner page blocks connections to any other host.

If you supply a GitHub token it is held in memory until you close or reload the page. It is sent only to api.github.com and is never written to browser storage.

Results stay on your screen. There is no share link, because a report can describe weaknesses the project has not fixed yet.

Limits

  • Without a token GitHub allows 60 API requests an hour per address. A review uses about five.
  • File contents over 1 MB, binary files, and repositories with very large file trees are only partly covered. The report says so when that happens.
